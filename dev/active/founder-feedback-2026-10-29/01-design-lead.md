# 01 Design lead: IA / Today density / peer patterns

**A. Figure motion: CHANGE.** Motion in the set player is right (it is the one place a cue is read mid-set); Today thumbnails and brief rows stay still on purpose. Watch demo stays as the real-video escape hatch. Shot 1 shows the figure at the top of the rep with the 'L' marker, so I cannot tell if it loops. Check device first: `SetView.tsx:534` `playing={!demoOpen}`, and any reduced-motion / battery-saver gate (Android battery saver and "remove animations" both kill CSS/rAF motion). If it does move, the amplitude/tempo is too subtle: slow the loop to the rep tempo and give the moving limb the teal accent. Do not add motion to Today thumbnails (nothing to learn there; costs battery and attention). Lead-lifts-only is correct: accessory figures are generic; animating all of them multiplies maintenance for no new information.

**B. Today below the fold: CHANGE (cut ~half).**
- Check card (`HeroStateCard.tsx`): "No check yet" at full card weight is the loudest thing on the page for a null state. Collapse to a single 48px row ("Morning check · not yet" + chevron) until done; expand to the full card only when there is a result or an amber/red state. The safety gate is untouched, only the empty state shrinks.
- "First hip check +1 more" (`SignalsStrip.tsx:425`): keep, it is already collapsed. But it duplicates the check card. Merge: one "Check" row, hip prompts live inside it. Hip-program only stays.
- "2 tracks scheduled…snooze from Profile" banner (`TodaySession.tsx`): CUT as a permanent banner. Two hero cards already say two tracks. The second paragraph is pure advice. Show only when total estimated time > ~90 min or on first multi-track day, dismissible, with the snooze action inline (a link to Profile in a PWA is a detour).
- "Heavy squat day, keep conditioning light" (`RunSlotCard.tsx:907`): wrong place. It says "the plan schedules nothing here", i.e. an absence rendered as a full card, on the day the heavy lift is the hero. Demote to one muted line under the hero's day strip, or into Plan day detail. Never above/at card height on Today.
- Target: Today = hero cards + one status row + at most one nudge. Rule: absence never gets a card.

**C. Progress overview: BUILD (small, session-insights first).** GOWOD's ring works because mobility has a retest score. Terav tracks differ per program; a per-track ring invents a composite the data cannot back, and that breaks "no new claims". Build instead a finished-session summary, rule-based, no LLM: 2-4 lines, each tied to a log signal (e.g. "Front squat 5x5 @80 kg all Easy; last week 115x3: working max looks low, review?" with a link to the existing confirm-first proposal, not a silent change). Template-driven from existing signals, so each line cites a log signal by construction; Haiku only for phrasing later, not v1. Per-track "retest delta" (e.g. overhead mobility start vs week-10 retest) is the only honest ring-equivalent; defer to Record. Surface: done screen of the set player/brief, not Today.

**D. Brief when all done: CHANGE.** "Log an extra session" is irrelevant right after finishing; remove it from the done state (keep in a pre-start/off-plan context). Empty page is fine, but fill the dead space with the done summary (C) and demote "Finish session" to a real completed state ("Done · 2 of 2 moves") instead of a primary button that implies work remains. "How to run this" stays collapsed.

**E. Back in guided set: BUILD.** Back must be a view, not a mutation. `FollowAlong.tsx:485`: make Back step into a read-only review of the finished set (result shown, "Redo this set" as secondary), with a forward "Back to current set" as the primary action. Only Redo is destructive; Skip stays for skipping. This is a trust bug in a timed flow: any navigation that costs data without confirmation violates the consent-first rule.

**Top 3:** 1) E (data-losing navigation), 2) B (Today diet: shrink empty check card, cut snooze banner, demote heavy-day card), 3) C (rule-based session insights on done screen; skip the ring).
