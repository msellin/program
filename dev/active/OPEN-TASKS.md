## Closed 2026-09-11

**CI was red for a reason that had nothing to do with staleness.** Three runs
failed on `task-index: STALE` since the guard landed on 2026-09-08, and the
message was wrong every time it printed. `actions/checkout` defaults to depth
1, so the runner holds a single parentless commit and `git log -1 -- <path>`
returns it for EVERY tracked file: all sixteen workstreams come back stamped
with HEAD's date. The index CI generated could therefore never match the one
anyone committed, no matter how recently it was regenerated — and it was never
reproducible locally, because a normal clone has the history.

Verified by cloning this repo at `--depth 1` and diffing the dates:
saas-launch reads 2026-09-11 shallow against 2026-08-18 full, video-analysis
2026-09-11 against 2026-09-01, traffic 2026-09-11 against 2026-09-06.

Fixed with `fetch-depth: 0` rather than by loosening the test, because the
dates are the point — the script's own docstring says a workstream with 81 open
items and no commits for three weeks is telling you something a count alone
hides, and under a shallow clone every one of those dates reads as today. The
shallow case now prints its own diagnostic instead of sending the reader to
regenerate a correct file, and `fetch-depth: 0` is pinned by a test bounded to
the verify job. Both were mutation-tested; the bounded-slice version caught a
mutation that moved the setting to a later job, which the first draft did not.


**H2 — `store.cycle.phase_id` deleted.** Written in six places, read in none;
the wire option had died with `coach-client.ts`. Removed from `storeSchema` and
from all 23 call sites. The delete rests on Zod stripping unknown keys, so every
stored store and all 37 persona artifacts still parse — that was a code comment
and is now `store-schema-compat.test.ts`, because this repo has twice shipped
keys that Zod silently discarded and the silence is what let them survive.

**CLAUDE.md's program count.** It said "5 shipping programs" while the manifest
held nine, and had been wrong since `first-strict-pullup`, `muscle-up` and
`engine-builder-block-2` shipped. Wrong in the direction that matters: a session
briefed on five reasons about five, and this repo's recurring defect class —
a hip program's symptom map rendered to everyone, a load axis hardcoded to two
programs' lifts — is exactly what you miss when you think the catalog is
smaller than it is. Now pinned to the manifest in `data-integrity.test.ts`.
Mutation-tested, and the first version FAILED that test: it searched all of
CLAUDE.md, so deleting `muscle-up` from the catalog list still passed because
the Validation section mentions muscle-up for an unrelated reason. Scoped to
the paragraph.
