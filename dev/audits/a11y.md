# Accessibility audit — warm-dark v2

**Target:** https://program-v2.pages.dev
**Source:** `/Users/margussellin/www/program/next-app/`
**Method:** axe-core 4.x injected via Playwright at iPhone-13 viewport (390×844, DPR 2), plus programmatic keyboard / modal / target-size probes and hand-checked WCAG contrast against the CSS token table in `src/app/globals.css`.
**Palette under audit:** Lane A warm-dark (canvas `#0E0F12`, surface `#16181C`, ink `#D6D9DE`, accent bronze `#C89666`, slate `#4A8894`).
**Date:** 2026-08-06.

---

## 1. Executive verdict

**Not WCAG 2.2 AA compliant.** Three actively broken groups: (a) the entire Morning-check slider set has zero programmatic labels — that is a **critical** violation (axe rule `label`, five nodes); (b) the SessionActions and Watch-demo modals have no focus management — no move-in, no trap, no Escape-to-close, no aria-labelledby wiring; (c) the Progress chart is still using **light-theme** hex codes (grid `#E5EAEE`, axis text `#64757F`, series `#A63A32` / `#2B5F7E` / `#2F7D5D`) that were never re-tokenised, and every one of them fails AA on the warm-dark surface.

Beyond those, the `slate` token (`#4A8894`) — used ubiquitously for suggestion top-set text, cue toggles, "Set TM", and the Prev / Rx column — sits at 4.44:1 on `#16181C` and fails AA body text on every card. Same token drives the `lat-left` L marker on the laterality spine (3.92:1 on `#20232A`) which fails both AA body and AA large. On the plus side: focus rings are visible bronze (2px outline, ratio ~7:1 on both canvas and surface), landmarks are correct, and the number/reps/RPE inputs all carry proper `aria-label`s.

**Rough scoring:** ~15 real axe violations across 5 routes (1 critical, all others serious), plus 4 categories of manual findings not caught by axe. Full AA compliance is 3–4 focused edits away (see §5).

#### `aria-prohibited-attr` — incomplete, but real
**Route:** `/` and `/extras/`.

```html
<span aria-label="Personal record" class="col-span-6 flex ... mono-caps text-accent" ...>
  <span class="inline-block w-1.5 h-1.5 rounded-full bg-accent" />
  PR · 90 × 5
</span>
```
`aria-label` on a `<span>` with no explicit role is prohibited by ARIA 1.2 (implicit `generic` role disallows name). **File:** `next-app/src/components/workout/SetRow.tsx:100–108`. Either give the span `role="status"` (also announces the PR arrival) or wrap it in a `<mark>` / `<strong>` and drop the aria-label.

## 4. Manual findings

Every item below was verified by direct DOM probing at 390×844 on the production site. Raw dumps at `/tmp/pw-audit/manual-findings.json`.

### 4.1 Modal focus management (both dialogs are broken)

**Files:** `next-app/src/components/workout/SessionActions.tsx:109–160,178–222`, `next-app/src/components/workout/ExerciseCard.tsx:265–310`.

Both `role="dialog" aria-modal="true"` are set. That's the extent of the a11y wiring. Verified behaviours on Skip modal (`ConfirmSheet`):

| Behaviour | Expected | Actual |
|---|---|---|
| Focus moves into dialog on open | first focusable element (Cancel or reason input) | Focus **stays on trigger button** (`activeTag=BUTTON, text=Skip today`, `focusInside=false`) |
| `Escape` closes dialog | yes | **no** — dialog stays open |
| `Tab` cycles inside dialog | yes | **no** — after 5 Tabs focus escapes onto the "TODAY" Hero card and continues down the page under the backdrop |
| Focus returns to trigger on close | yes | ok — the trigger keeps DOM focus because it never lost it. This is a side-effect of the previous bug, not a fix |
| `aria-labelledby` points to the visible heading | recommended | no — dialog has no `aria-label` and no `aria-labelledby`. The visible "Skip today's session?" `<p>` is not identified as the accessible name |
| Backdrop click closes | yes | ok (mousedown handler on outer div) |

**Repro:** open the site → scroll to Session actions → Tab to "Skip today" → Enter → press Escape → dialog stays. Press Tab six times → focus lands on "TODAY" hero card behind the backdrop.

Video modal (`ExerciseCard.tsx:265`) has identical behaviours: `focusInside: false` on open, `Escape` does not close, no `aria-labelledby` pointing at the `<h3>` on line 277.

### 4.2 Bottom nav overflows on iPhone-13 viewport

**File:** `next-app/src/components/nav/BottomNav.tsx:35`.

`<ul>` scrollWidth 544 vs clientWidth 390 → 154px of Data + Guide is off-screen. `overflow-x-auto` on the `<ul>` masks it silently: no scroll indicator, no shadow, no chevron. Users on 390-wide viewports (iPhone 13, 14, 15 non-Pro/Max) can't reach the Data or Guide tab without discovering they can pan. Each tab hits 68×53 which is 44-wide but not 44-tall (see §4.3), and there are 8 of them.

Fix options: drop Guide/Extras/Week from bottom nav into a "More" tab, or reduce to icons-only at ≤390px.

### 4.4 Semantic-state is colour-only for `derived_state`

**File:** `next-app/src/components/workout/HeroStateCard.tsx:26-44`.

The Hero card communicates green/amber/red by:
- Colour of the ring (`ring-green/30` etc)
- Colour of the 2px dot (`.bg-green/.bg-amber/.bg-red`)
- The English copy — "Ready to lift" vs "Load with care" vs "Rest today" — which *does* carry the state semantically

The copy saves this from being a full WCAG 1.4.1 violation. But the compact `SuggestionBox` state label at the top ("Suggested today" vs "Suggested — hold (amber day)" vs "Suggested — reduced (red day)") is the only non-colour indication in the box; the top-set number is the same slate colour regardless of state, and both amber/red are announced only in the small mono-caps overline. Icon shapes should be added (e.g. check / warning / stop-circle from lucide) so that a colour-blind or B/W screenshot still communicates state.

### 4.5 Laterality markers are colour-only *and* 9px

**File:** `next-app/src/components/workout/ExerciseCard.tsx:72-87`, `next-app/src/app/check/page.tsx:161-167`.

The spine on ExerciseCard shows either an L or an R (never both) coloured to indicate "extra set on this side". A user with colour-vision deficiency who cannot distinguish `#4A8894` teal from `#8A8F9A` grey sees no lateral emphasis. Text is 9px (`text-[9px]`), far below the 12px accessibility floor. The L / R pill on `/check/` is 10px with high-contrast surface-on-lat-* — better, but the L pill fails contrast (4.44:1).

Recommend: (a) increase to 11-12px; (b) add a border, arrow, or duplicate-glyph pattern for the emphasised side; (c) add a `<span class="sr-only">Extra set on left</span>` since a screen reader currently hears "L R" as characters with no context.

### 4.6 `prefers-reduced-motion` not honoured

**File:** `next-app/src/components/workout/SetRow.tsx:100-108`.

Test emulated `prefers-reduced-motion: reduce`. Two active animations detected: the PR-tag `tag-in` keyframe still fires at 260ms. `globals.css:106-109` defines the keyframe with no media guard, and `SetRow.tsx:104` applies it via inline `style={{ animation: '...' }}` which bypasses any CSS `@media (prefers-reduced-motion)` override you might add later without also gating the inline style.

Fix: move the animation into a class, then wrap:
```css
@media (prefers-reduced-motion: reduce) {
  .pr-tag-anim { animation: none; }
}
```
Also gate the `active:scale-[0.98]` on HeroStateCard.tsx:65 and any Tailwind `transition-*` on interactive elements.

### 4.7 Placeholder-as-label pattern in SetRow

**File:** `next-app/src/components/workout/SetRow.tsx:40-71`.

Each input has `aria-label` (good — confirmed present in DOM: `Set 1 weight`, `Set 1 reps`, `Set 1 RPE`) but the visible label is the placeholder (`kg`, `reps`, `RPE`), which disappears as soon as the user types. Once the row has a value, sighted keyboard users returning to a filled row have no on-screen indication that column 3 is "reps" and column 4 is "RPE". The `Weight kg / Reps / RPE` header row above the sets is separated by up to 6 rows of inputs — not a WCAG failure, but a discoverability issue that combines badly with the 34px row height.

### 4.8 Landmarks and headings — actually correct

Verified on `/` and `/progress/`:

```
navCount: 1 (label="Primary")
mainCount: 1
h1Count: 1  (per page — "Today", "Progress", "Data", "Morning check", "Guide" etc.)
headerCount: 10  — inside cards. Fine; nested <header> is legal.
```

Neither `<aside>` nor `<footer>` are used. Bottom nav is labelled `"Primary"` as spec required. Confirmed.

### 4.9 Keyboard navigation reaches everything (aside from the modal escape defect)

Tab traversal on Today lands on: date nav (3 buttons) → hero card link → laterality skip → checkbox → weight → reps → RPE → remove → next set × N → Add set → Notes textarea → Cues → then next exercise. No mouse-only handlers observed on the primary flow. `Enter` and `Space` fire on all `<button>` and `<a>` elements as expected.

### 4.10 `aria-label` on `<span>` (PR badge)

Already covered under §2. The workaround `role="status"` also delivers the announce-on-appear behaviour, which is the intent.

## 5. Recommendations (ranked by effort)

### R1 — Add `aria-label` (or wrap in `<label>`) on every `/check/` slider — **critical, 5 minute fix**
File: `src/app/check/page.tsx:170-178`. Change:
```tsx
<input type="range" aria-label={`${label}${suffix ? ` (${suffix})` : ''}: ${value}`} ... />
```
Or promote the outer `<div>` to `<label>` and give it `htmlFor` linked to `id={slug(label)}`. Fixes the only critical axe violation.

### R2 — Retint `--color-slate` and migrate the chart palette — **~20 minutes, unblocks 25+ contrast violations**
`slate` currently `#4A8894` (4.44:1 on surface). Lift to `#6BA5B1` (~5.8:1) or `#7AB3BE` (~6.4:1). This automatically fixes every SuggestionBox top-set, Cues toggle, TM chip, and Prev/Rx column. Bump `--color-muted` from `#8A8F9A` to `#9BA0AB` at the same time to give headroom under the semantic tints.

In `src/components/charts/SymptomLoadChart.tsx`, replace hex literals with the retinted tokens:
- `stroke="#E5EAEE"` (grid) → `var(--color-line-soft)` or `#2A2E37`
- `fill: "#64757F"` (axis text) → `var(--color-muted)` after retint
- Bar fill `#A63A32` → `var(--color-red)` `#E5654B` (5.33:1)
- Squat line `#2B5F7E` → the retinted slate
- Pull line `#2F7D5D` → `var(--color-green)` `#5FB37A` (6.95:1)
- Legend `wrapperStyle.color` needs an explicit `var(--color-ink)`

Recharts pulls colour from inline style, so tokens have to be read via `getComputedStyle(document.documentElement).getPropertyValue('--color-slate')` at render time. Alternative: hard-code the retinted hex directly.

### R3 — Add proper modal behaviour — **~1 hour, fixes two dialogs**
Files: `SessionActions.tsx:109`, `SessionActions.tsx:178`, `ExerciseCard.tsx:265`.

Adopt Radix or headless-ui Dialog, OR write a tiny hook:
```tsx
useEffect(() => {
  const previousActive = document.activeElement as HTMLElement | null;
  const firstFocusable = dialogRef.current?.querySelector<HTMLElement>('button, input, [tabindex]:not([tabindex="-1"])');
  firstFocusable?.focus();
  const onKey = (e: KeyboardEvent) => {
    if (e.key === 'Escape') onCancel();
    if (e.key === 'Tab') { /* trap logic */ }
  };
  document.addEventListener('keydown', onKey);
  return () => {
    document.removeEventListener('keydown', onKey);
    previousActive?.focus();
  };
}, []);
```
Also add `aria-labelledby="dialog-title"` and put `id="dialog-title"` on the visible heading. Fixes Escape, tab-trap, initial focus, and dialog naming in one pass.

### R4 — Bump touch targets on the primary logging flow — **~15 minutes**
- `DateNav.tsx:31,45,55`: `p-2` → `p-3` (arrows become 42×42; still below spec; use `p-[13px]` or `w-11 h-11`).
- `SetRow.tsx:88` remove-set trash: `w-6 h-6` → `w-11 h-11` with the icon still 14px, or move remove into a swipe / a long-press.
- `SetRow.tsx:54,70,86` inputs: `py-1.5` → `py-2.5` on mobile via `py-2.5 sm:py-1.5` (or use a 44px `min-h`).
- `ExerciseCard.tsx:92-98` checkbox: wrap the whole title row in a padded label so tapping anywhere on the title toggles done, keeping the 20px visual but a 44px hit area.

### R5 — Non-colour state indicators & animation guard — **~30 minutes together**
- Add lucide `CheckCircle`, `AlertTriangle`, `OctagonAlert` (or similar) beside the state text on `HeroStateCard`, `Verdict`, and `SuggestionBox` state labels. Small enough to also help sighted users scan.
- Increase L/R spine text from `text-[9px]` to `text-[11px]` and add `sr-only` full-word description on emphasis (`Extra set on left`).
- Move the PR-tag animation off inline style; add:
  ```css
  @media (prefers-reduced-motion: reduce) {
    .pr-tag-anim, .card-in-anim { animation: none !important; }
    * { transition-duration: 0.01ms !important; scroll-behavior: auto !important; }
  }
  ```
- Change `<span aria-label="Personal record">` to `<span role="status" aria-label="Personal record">` (SetRow.tsx:100) — fixes the aria-prohibited-attr incomplete and gives useful announce-on-appear behaviour.
