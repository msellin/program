# Engine Builder — Comprehensive Audit (2026-08-18)

Read-only audit. Persona bundle: `next-app/tests/e2e/artifacts/personas/persona-engine/`.

## 1. Verdict

Engine Builder Block 1 is the strongest-authored program in the catalog — the JSON is honest, the phases run consecutively, the copy matches the landing promise, and the shipped Vector-A fixes (`resting_hr_morning` typo + `pace_500m` filter drop) do land in the current file. **But the persona-engine artifact is not evidence of the engine actually adapting** because the simulator harness never logs cardio sessions for this program — the 60-day "Zone-2 log" is 60 days of empty `exercises: {}` with a life-load slider parked at 4. As a result the Today screen shows an impossible superposition of "Your plan is built · Week 1 opens with z1 steady" and "YOU FINISHED · 6 weeks logged. No retest metrics recorded" simultaneously (`text/01-today.txt:5-46`, `mobile/01-today.png`) — a P0 UX contradiction that any user coming back after a real absence will hit. The engine's retest cards, adherence chart, and per-track adherence all render zeroed out (`text/05-progress.txt:38-66`), which is faithful to the empty log but exposes several downstream honesty gaps.

## 2. P0 findings

- **P0-1 · Today screen contradicts itself.** The persona sees the "Your Engine composite (Block 1) plan is built · Week 1 opens with z1 steady" card AND the "YOU FINISHED · 6 weeks logged. Nice. · No retest metrics recorded" completion card on the same view (`text/01-today.txt:5-17` vs `:36-46`; `mobile/01-today.png`). Root cause is the phase clock has walked to Week 8 (`text/01-today.txt:24` "Week 8 — deload and retest") while `store.cycle.phase_id: null` (`final-store.json:552-556`) and 0 logged sessions makes the completion-heuristic fire too. Two separate "state of the program" summaries render without either yielding to the other. Any user who starts, misses the whole first month, then reopens the app will see this exact contradiction.
- **P0-2 · Persona simulator writes zero cardio sessions for a cardio-first program.** `tests/e2e/harness/simulator-v2.ts:20` whitelists only `back_squat_highbar`, `block_pull_midshin`, `front_squat` and writes to `store.logs[date].exercises[key]`. There is no `runs[]` write path (`simulator-v2.ts:247-277`). Result: `final-store.json` contains 60 days of morning symptom checks and `exercises: {}` — no runs, no retest readings, no `dismissed_proposals`, no `day_adjustments`, no `intake_answers`, no `capability_profile`. **This persona cannot answer the "did the engine actually adapt?" question the audit needs answered.** Fix belongs in the harness (add a cardio-session write path for endurance-category programs), not in the app.
- **P0-3 · Retest cards render as "—" in Progress and Report even when the persona is at Week 8.** `text/05-progress.txt:30-66`, `text/10-report.txt:44-80`. Combined with the P0-1 "6 weeks logged. Nice." celebration on Today, the app is congratulating a user for a program they didn't complete AND admitting it has no data — the two states should not coexist. If persona logs are empty, Today's completion card should not fire at all.

## 3. P1 findings

- **P1-1 · Report page shows garbled overview stat.** `text/10-report.txt:40` renders `MORNING CHECK 48g · 1047?`. Screenshot confirms (`mobile/10-report.png` — "48g · 1047?"). Likely a `48 green · 104 …` string being truncated/glyph-swapped to `g` and `?`. Copy or render bug — either an emoji-fallback issue in the summary computation, or a printf mis-format. Highly visible on the shareable/print report.
- **P1-2 · Per-track adherence shows "0/14 done · 0%" with "11 UPCOMING · 3 SKIPPED".** `text/05-progress.txt:23-27`. Zero-of-fourteen for a persona alleged to be on week 8 is confusing because the surrounding copy says "Moved sessions don't count as misses — they're rescheduled work." This is technically correct given the empty log, but the framing makes a "your engine has been idle" state look like "you're doing fine, we just don't count moves." Consider a distinct empty-state ("Nothing logged in the last 28 days — retest window opens Thursday").
- **P1-3 · Intake tier-condition default-to-0 behaviour.** `engine-builder.json:414`: Foundation condition `cardio_hours_per_week < 1 || !can_sustain_20min_easy || recent_z1_max_minutes < 25`. Per `intake-tier.ts:69-73` + `:361-368`, unanswered questions default to 0. A user who reveals nothing lands on Foundation indistinguishably from a user who honestly qualifies for Foundation. Vector A flagged this; still open.
- **P1-4 · Retest metric #1 (`submax_hr_pace5_bpm`) now reads any easy run.** After the `pace_500m` filter drop, `engine-builder.json:1587` is `runs[].avg_hr where intensity == 'easy'`. `runLogSchema` does have `avg_hr` and `intensity` (per Vector A audit passing note). So the fix ships — the metric is now readable — but any casual easy-Z1 flush in a week outside the retest window will contribute to the trend slope. There is no pace-anchor discriminator ("submax HR *at 2:00/500m*") in the data, only in the `display_name` (`:1583`). The retest is honest about direction but not about the anchor claim the display makes.
- **P1-5 · `retest_metrics[1].source_ref` is now `resting_hr_morning`** (`engine-builder.json:1619`), matching `physical_tests[0].id` (`:309`). Vector A's typo fix is shipped ✓. However the current-value read goes through `capability_profile["resting_hr_morning"].measured_value` (`retest-evaluator.ts:130-149`). The `Log a new reading` button on Progress (`text/05-progress.txt:68`) must actually write to `capability_profile.resting_hr_morning.measured_value` for the retest to move. Without a persona artifact that exercises that button, unverified end-to-end. Recommend a smoke test.
- **P1-6 · "Referenced/reviewed/verified" chip legend appears once, at top of Programs list.** `text/06-programs.txt:6`. Not repeated per-card, and not on the preview page (`text/07-programs-active.txt` only shows the two chips `ACTIVE REFERENCED`). A new user tapping in from Programs → preview loses the legend. Suggest a `title` tooltip is already on the chip (per `ProgramPreviewClient.tsx:170-183` — yes, there is) but on mobile there is no hover; the tooltip is invisible.
- **P1-7 · "6 weeks logged. Nice." completion copy is off-tone.** `text/01-today.txt:40`. Terav's landing voice is precise ("Every proposal cites a study", "focused improvement, not a full plan"). "Nice." reads like Duolingo. Copy tone drift.
- **P1-8 · Coach tab is "Coming soon".** `text/03-coach.txt:6-11`. The Programs catalog copy is honest about `REFERENCED = every claim cites a paper` but the Coach tab explicitly promises "am I ready to add the Norwegian 4×4?" — a live feature that isn't shipped. Two options: (a) hide the Coach tab from bottom nav in the ⋮ menu (per `text/11-guide.txt:76` it *is* behind the ⋮ menu), or (b) reword the placeholder so it doesn't imply future-tense certainty about what will ship.

## 4. P2 findings

- **P2-1 · Extras page lists all six blocks without a "why here" header.** `text/12-extras.txt:10-36`. Six anonymous cards ("Zone 1/2 steady-state — 1 exercise", "Norwegian 4x4 VO2max intervals — 1 exercise") — no phase context, no "this is your prescribed session for today" callout. A user could log a session against `block_norwegian_4x4` in week 2 (before it's prescribed) and it would count toward retest, subverting the polarised progression rationale (`engine-builder.json:1178`).
- **P2-2 · History heatmap shows all-green for 60 days** despite the log containing no cardio sessions (`text/04-history.txt:8-24`). Root cause: `derived_state: "green"` is written on every symptom check regardless of whether a session was logged. Heatmap-green implies "trained + felt fine", but this state is "no training, felt fine". Consider a distinct swatch for "check only, no session".
- **P2-3 · Guide tab is high quality but doesn't link to the program's `evidence_base.references[]`.** `text/11-guide.txt` covers Z1/Z2/threshold/VO2max/taper cleanly but points to no citations. `engine-builder.json:1225-1541` has 30+ references with URLs. A "See the studies →" link per section would deliver on the landing's "92 primary studies. Every session cites its research."
- **P2-4 · Retest cadence mismatch between primary metric (`cadence_weeks: 4`) and target `at_week: 8`.** `engine-builder.json:1588-1611`. If cadence is 4, the mid-block week-4 evaluator (`retest_metrics_mid_block[]` at `:1722`) should trigger; but the target `at_week: 8` is what Progress renders. Result: `text/05-progress.txt:36` says `CHECK AT WEEK 8` even though `cadence_weeks: 4` implies a week-4 checkpoint exists. Either the cadence is aspirational or the display is under-serving.
- **P2-5 · `signal_completeness.would_additionally_use` at `engine-builder.json:1682-1694` promises Garmin/Whoop/Apple Watch integration.** No such integration exists in the app. Same overpromise pattern as the Coach placeholder.
- **P2-6 · Life-load slider parked at 4 all 60 days** (`final-store.json:12,22,32,…`) — an artifact of the simulator archetype, but exposes that Today's proposal ("LIFE LOAD 4/10 · APPLY 5% LIGHTER") fires on a mid-scale life load with no logged fatigue signal to justify it. `mobile/01-today.png` shows "Because: Fatigue signals in recent notes." — but there are no notes. Likely a stale-context detection or a wire-up gap in the reasoning attribution.
- **P2-7 · Programs catalog puts "More programs land as they're authored." at the very bottom** (`text/06-programs.txt:95`). Fine, but no CTA for a user who wants to be notified. Small conversion gap.
- **P2-8 · Manifest tag `"block-1"` (`manifest.json:49`)** exists but no UI surfaces it. Block-1/2/3 is not discoverable as a series from the catalog — you have to open Engine Builder Block 2's card to realise it's part of an arc. A "3-block series" chip on Block 1 would set expectations.

## 5. Adaptation verification

Verdict: **cannot verify from persona artifacts** because of P0-2.

Concrete evidence gaps in `final-store.json`:

- `phase_id: null` (`:553`) — the engine never wrote a phase pointer during simulated activation. Either the sim skipped the intake commit path or the store shape doesn't require it. The Today screen (`text/01-today.txt:16-38`) *does* display "Week 1 opens with z1 steady" AND "Week 8 — deload and retest", so the schedule layer is reading `phase.starts / phase.ends` correctly against `active_program_started_at: 2026-07-01T08:00:01.447Z` (`:568`). 48 days elapsed = week 7 or 8, matches. So phase advancement via elapsed-time works ✓, but `store.cycle.phase_id` was never updated — dead field or lazy write.
- No `runs[]` in any day (all `exercises: {}`). No `dismissed_proposals` field. No `day_adjustments`. No `tm_bump_history`. No `capability_profile`. No `intake_answers`. **Nothing the confirm-first mechanic writes appears in the store.** Either the simulator bypasses those write paths entirely, or those fields only get created lazily on first interaction — the audit cannot distinguish.
- Retest window: JSON declares Week 8 midweek (`engine-builder.json:562-577`). Week view for 17-23 Aug shows `Thu 20 Aug · Block 1 retest` (`text/02-week.txt:34-38`, `mobile/02-week.png`) ✓ — schedule correctly places retest on Thursday of week 8. Retest firing at the right calendar day works ✓.
- Today's proposal card (`text/01-today.txt:26-33`): "FATIGUE OR PAIN FLAGGED TODAY · LIFE LOAD 4/10 · Source: Halson 2014 · APPLY 5% LIGHTER". The proposal has a citation ✓ (matches "Every change cites a study" landing promise) and offers a confirm-first Accept/Ignore ✓. But the reason "Fatigue signals in recent notes" is false — there are no notes (empty in every day of `final-store.json`). The reason-string generator is decoupled from the actual signal that triggered.
- The engine's understanding does NOT evolve visibly from anything in the artifact bundle — Progress's "HOW THE ENGINE READS YOU" section (`text/05-progress.txt:17`) is a collapsed accordion with no persisted signals surfaced, and the persona has no calibration prompt or intake tier record to reference.

Recommend: rerun the persona with a simulator patch that writes at least one `runs[]` entry per scheduled Z1/Z2/tempo/4×4 day, plus a real `intake_answers` commit and one `capability_profile.resting_hr_morning.measured_value` update at week 4 (to exercise `retest_metrics_mid_block[]`). Without those, the persona proves the app renders — not that the engine adapts.

## 7. What worked

- **JSON authoring is high quality.** Phase dates run consecutively (`engine-builder.json:461-579`), all block IDs resolve, safety gates work with boolean/select serialisation, weekly template shape matches the schedule engine, plan tiers cover cardio_hours_per_week × recent_z1_max_minutes cleanly.
- **Preview page is honest and complete.** `text/07-programs-active.txt` explicitly names arc position, retest protocol, low-impact modality gate through week 4, and the baseline setup expectation — matches `who_this_is_for` / `what_youll_achieve` in the JSON verbatim.
- **Vector A's shipped fixes are actually shipped.** `pace_500m` filter dropped (`engine-builder.json:1587`), `resting_hr_morning` typo corrected (`engine-builder.json:1619` vs `:309`).
- **Evidence base is thorough.** 30+ references with URLs, per-session rationale with citations, honest tier variance disclosure via HERITAGE and Ross 2015. This is the model the other four catalog programs should aspire to.
- **Concurrent-training policy is defensible.** RPE cap 7, 2-3 sessions max, 6h same-day separation, all cited (Hickson, Wilson-Loenneke, Docherty-Sporer, Robineau, Eddens). Explains the "not a full plan" positioning at authoring level.
- **Guide tab endurance-terms glossary is one of the strongest pieces of app copy shipped.** Z1/Z2/threshold/4×4/500m split/taper defined precisely with citations inline (`text/11-guide.txt:14-26`).
- **Week view is clean.** `mobile/02-week.png` reads at a glance; the week-header prescription callout for week 8 is exactly the right dose of context.

## 8. Recommended fix order

1. **P0-1** — Today should not render both "Your plan is built · Week 1 opens" and "YOU FINISHED · 6 weeks logged" simultaneously. Add a mutual-exclusion guard: if `phase.name` includes "retest" AND at least one session has been logged in the last 14 days → completion card; otherwise → plan-built card only. Look at the Today screen orchestrator (likely in `next-app/src/app/(app)/page.tsx` or equivalent).
2. **P0-2** — Persona harness: extend `tests/e2e/harness/simulator-v2.ts:247-277` to write a `runs[]` entry for endurance category programs, plus stamp `intake_answers` + `capability_profile` at simulated intake commit. Without this the persona-engine artifact bundle is not fit for adaptation verification.
3. **P0-3 / P1-2** — Progress page adherence "0/14 done" needs a distinct empty-state, not "0%". "Nothing logged yet — first session opens Thursday" is honest and doesn't imply failure.
4. **P1-1** — Debug `48g · 1047?` on Report page. Likely a printf mis-format or emoji fallback in the summary computation.
5. **P1-4** — Either add a pace-anchor filter to the `submax_hr_pace5_bpm` source_ref (once the run schema grows a pace field) or rename the metric to "Submax HR on easy days" so the display doesn't overclaim.
6. **P1-8** — Reword or hide Coach tab so the placeholder doesn't imply live functionality.
7. **P1-6** — Add a small "what these chips mean" line on the preview page since the mobile tooltip is dead.
8. **P1-3** — Add an "unanswered" tier state so Foundation-by-default is distinguishable from Foundation-by-fit.
9. **P2-3** — Link Guide sections to `evidence_base.references[]` to cash the "92 studies" landing promise.
10. **P2-8** — Chip Block 1 with a "Block 1 of 3" tag on the catalog card; users need to see the arc.
11. **P2-6** — Fix Today's "Because: Fatigue signals in recent notes" reason string when the notes are empty. Attribute honestly ("Life load 4/10 is above baseline") or don't fire the card.
12. **P2-2** — History heatmap needs a separate swatch for "check only, no session"; all-green for 60 days of no training is misleading.
